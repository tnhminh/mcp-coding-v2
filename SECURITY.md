# SECURITY

Security posture is deny-by-default. Production controls are not yet complete.

Implemented baseline: localhost HTTP bind, Host/Origin validation, minimal non-sensitive health payload, structured log redaction, registry-aware project-root canonicalization and adversarial traversal/junction/symlink/nested-project/Windows path isolation tests.

Privileged local capabilities require a valid project-bound permission session; enabled global/project deny policies override grants. When a session ID is omitted, authorization may resolve a deterministic same-principal dominant capability envelope, while incomparable envelopes or different principals remain ambiguous and fail closed. Secure Filesystem tools deny sensitive credential paths, private-key material and binary/NUL content. Normal whole-file text reads/writes remain tightly bounded; dedicated range read/line-replacement operations support authorized text files up to 16 MiB while retaining whole-file SHA-256 concurrency. Writes use canonical re-resolution, temp-file + rename commit and optimistic concurrency; batch patch prevalidates all targets, supports sequential same-file exact patches only when they share the original SHA, and attempts rollback; delete requires a persisted backup. Directory traversal does not follow symlinks.

Structured command execution requires `command.run`, exposes only fixed task kinds plus validated structured dependency/install/codegen recipes, never accepts caller-provided raw shell, inherits only an explicit safe toolchain/public-frontend environment subset, caps/redacts captured output without treating truncation itself as task failure, enforces timeouts and cleans process trees. Package mutation recipes validate registry package syntax and recognized maintenance/codegen script names before execution. On Windows, package-manager commands use a fixed manager/argv construction through `cmd.exe`; custom `.mcp/tasks.json` profiles remain direct executable+argv and reject `.cmd/.bat` shims. `apply_and_verify` rolls back new regressions by default; a byte/evidence-equivalent pre-existing `source_failure` may be recorded as `baseline_accepted`, but that state remains explicitly unverified and cannot satisfy AI Job completion. Missing structured verifiers are represented as deferred rather than fabricated success.

Project Brain only enumerates/reads through the permission-gated Secure Filesystem surface. Persistent Brain snapshots store bounded file metadata, hashes, symbol/import/reference/test/config graph data but do not persist source-file content snippets. Invalid snapshot JSON is removed and state fails closed to `not_indexed`; context snippets are generated on demand from current authorized files.

Persistent AI Jobs do not persist permission-session identifiers. Every create/cycle/status/complete/cancel access is re-authorized against current project/session/policy state. Job transitions are explicit and SQLite compare-and-set prevents stale concurrent state overwrite; completion is gated on a verified cycle reaching `awaiting_review`.

Preview/browser execution is loopback-only. Static previews use the same credential-path classifier as Secure Filesystem and deny hidden/internal paths and credential JSON names while serving only an explicit supported asset/MIME set. Browser review accepts only a runtime-issued `preview_id` plus relative path, denies external page-side HTTP/WebSocket traffic by default, allows only explicitly configured trusted-local origins through `MCP_BROWSER_ALLOWED_ORIGINS`, blocks service workers, bounds captured evidence and uses installed local Edge/Chrome without downloading a browser bundle. Control Center preview/job administrative APIs remain under the same loopback Host/Origin guard and delegate authorization to the underlying services; a read-only access snapshot lets the UI avoid unauthorized probing without weakening protected endpoints. Arbitrary browser URLs remain unavailable.

Audit/Usage persistence records operation metadata rather than operation payloads. Automatic MCP audit stores tool name, project ID, result, duration, payload byte count and only a boolean indicating whether a permission-session reference was supplied; it does not persist tool arguments, prompt/file content, API keys or permission-session bearer IDs. Mutating Control Center API audit records method/path/result/duration without request bodies. LLM usage ingestion stores provider/model/token/cost metadata only when explicitly supplied by a trusted local adapter; missing ChatGPT-via-MCP token data is represented as `unavailable`, never estimated implicitly.

Residual risk: filesystem pathname checks reduce but cannot mathematically eliminate all OS-level TOCTOU races without descriptor-relative/open-handle APIs. Repository-controlled task definitions and recognized dev-preview scripts are trusted host code once a human grants `command.run`; browser routing controls page-side traffic but does not provide an OS-level network sandbox for the dev-server process itself. A trusted-local browser-origin allowlist must therefore be configured sparingly. Production identity/RBAC, audit actor identity/retention governance, complete secret scanning and stronger OS/process/network sandboxing remain incomplete. Brain indexing is intentionally capped and currently provides weighted lexical+graph retrieval rather than semantic embeddings/BM25; non-TS/JS indexed languages are lexical-only and reported as such.
